# 블록 설계 가이드 (참고용)

규칙이 아니라 참고다. 문제에 맞지 않으면 바꿔도 된다. 사용자가 사고 흐름대로 직접 옮길 수 있는지가 기준이다.

## 블록 크기와 수
- 블록 하나는 생각 한 단계다. 코드로 1–5줄 정도.
- 문제 하나에 3–8개 정도. 쉬운 문제는 적게, 단계가 많은 문제는 많게.
- 한 블록에 두 가지 결정을 넣지 않는다. 나누기 애매하면 사용자가 한 번에 떠올리는 단위로 묶는다.

## 순서
- 대개 문제에서 오는 값 → 담을 그릇 → 반복 → 조건 → 분기·결과 순서다.
- 사용자가 문제를 읽고 떠올리는 순서를 따른다. 코드 줄 순서와 다르면 생각 순서가 먼저다.

## kind 고르기
블록의 가장 바깥 구조로 정한다.
- 문제에서 바로 나오는 값을 변수에 담는다(입력의 길이, 입력에서 바로 읽는 값, 문제 글에 적힌 상수): var_from_problem
- 풀이 중에 만들어 쓰는 변수(빈 키-값 표·스택·덱·힙·표, 누적 값, 답을 담을 변수): var_during. return만 있는 블록도 풀이 중에 만든 값을 돌려주면 이것.
- for/while로 시작하는 블록: loop
- 조건을 따져 고르는 일(if 한 덩어리): condition
- 경우를 나눠 서로 다른 일을 한다(if와 else로 여러 갈래로 나누기, 일찍 돌려주기와 그 밖): branch
- 도우미 함수 정의 블록은 그 함수가 주로 하는 일의 종류.

## 유형별 흔한 뼈대 (예시일 뿐)
- 해시: 세는 그릇 → 하나씩 세기 → 빼거나 비교 → 남은 것 찾기
- 스택/큐: 자료구조 준비 → 하나씩 넣고 빼는 반복 → 꺼낼 조건 → 결과
- 힙: 힙 만들기 → 꺼내고 넣는 반복 → 멈출 조건 → 결과
- 정렬: 비교 기준 정하기 → 정렬 → 한 번 훑기
- 완전탐색: 후보 만들기 → 후보마다 확인 → 최선 고르기
- 탐욕법: 정렬 기준 → 하나씩 고르는 반복 → 고를 조건
- 동적계획법: 표 정의 → 시작 값 → 점화식 반복 → 답 위치
- DFS/BFS: 방문 표시와 시작 → 큐나 재귀 → 이웃 조건 → 결과
- 이분탐색: 범위 → 가운데 확인 반복 → 범위 줄이는 조건 → 답
- 그래프: 인접 리스트 → 거리 표 → 탐색 반복 → 갱신 조건

## checks (판정 신호)
- 사용자가 이 블록을 찾았다고 볼 신호 1–3개. 말로 적는다. 코드로 적지 않는다.
- 1번은 꼭 있어야 하는 핵심이다. 2·3번은 있으면 좋은 것이다.
- 예: "대출 기록을 처음부터 끝까지 한 권씩 차례로 훑는다", "처음 보는 제목은 0에서 시작해 횟수를 1 올린다"

## hints (생각하는 의자 질문)
- 3개. 0번 open: 이 블록이 왜 필요한지 묻는 열린 질문 → 1번 clue: 문제 글 문장 하나를 작은따옴표로 그대로 인용해 그 요구를 묻는 질문 → 2번 trace: 원소 2–4개짜리 예시를 손으로 따라가게 묻는 질문.
- 한국어 1–2문장, 물음표로 끝낸다. 정답 여부를 말하지 않는다.
- 칭찬·동의·판정 말('맞아요', '좋아요', '정답', '잘했어요', '좋은 질문' 등), 코드, 코드 펜스, 다른 블록의 이름을 쓰지 않는다.
- 1번의 인용은 문제 글에 있는 구절 그대로여야 한다. 없는 구절을 만들면 그 블록 질문은 저장되지 않는다.
- 예: "꽂히는 순서를 맞추려면 대출 기록을 어떤 순서로 하나씩 봐야 할까요?" → "'loans의 길이는 1 이상 100,000 이하입니다'를 보면 기록을 몇 번이나 훑는 방법이어야 할까요?" → "tide, tide가 차례로 들어오면 첫 번째와 두 번째 tide를 볼 때 그 제목의 횟수는 각각 얼마가 되어야 할까요?"
