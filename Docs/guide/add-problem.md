# 내 문제 넣기

이 문서는 가진 문제를 글이나 사진으로 넣어 등록하는 화면, 받는 입력과 한계, 제목과 예시를 스스로 채우는 규칙, 검증 표시, 모델이 필요한 부분을 설명한다.

## 한 화면

'내 문제 넣기'는 한 화면이다. 위에서 아래로 이렇게 놓인다.

1. 파일에서 가져오기와 '문제 글' 칸: 글을 붙여 넣거나 파일을 올린다.
2. 감지 줄: 글을 넣으면 "예시 3개를 채웠어요"처럼 무엇을 채웠는지 알린다. 같은 말을 읽어 주는 도구에도 알린다.
3. 제목: 글에서 찾은 제목이 들어간다. 찾지 못하면 비어 있고 "제목을 찾지 못했어요. 문제 이름을 직접 적어 주세요."가 뜬다.
4. 두 칸: 왼쪽 '문제'는 설명과 제한사항, 입력, 출력을 꾸며 보인다. 오른쪽 '입출력 예'는 채운 예시를 카드로 보이고 입출력 방식을 함께 적는다. 좁은 창에서는 위아래로 놓인다.
5. '더 정하기'(접혀 있음)와 '등록하고 풀러 가기'. 등록 단추는 스크롤해도 화면 아래에 남는다.

- 글을 넣을 때 누를 단추는 없다. 붙여 넣거나 적고 잠깐 멈추면 규칙으로 먼저 채운다. AI가 연결돼 있으면 붙여 넣은 글을 모델이 한 번 더 읽는다. 등록하기 전이어도 그 글이 모델에게 간다(아래 '모델이 보태는 것').
- '문제' 칸의 '원문 고치기'는 '문제 글' 칸으로 간다. 글을 고치면 다시 채운다.
- '입출력 예' 칸의 카드는 읽기만 한다. '고치기'를 누르면 케이스 칸이 열린다. 예시를 찾지 못하면 케이스 칸이 처음부터 열려 있다. '글의 입출력 예 보기'를 펴면 글의 입출력 예 구역(설명 포함)을 본다.
- 미리보기는 문제 화면과 같은 규칙으로 꾸민다. `$…$`, `$$…$$` 수식과 `10^5` 같은 위첨자가 문제 화면과 같게 보인다.
- 등록하면 그 문제의 풀이 화면으로 바로 간다. 같은 글을 이미 넣었으면 먼저 알리고, 한 번 더 누르면 넣는다.
- 등록 단추 옆에 등록하면 생기는 일이 한 줄로 뜬다. 연결돼 있으면 "등록하면 튜터가 풀이와 숨은 테스트를 준비해요. 모델을 쓰고 1분 안팎 걸려요. 그동안 풀기 시작해도 돼요.", 연결이 없으면 "AI가 연결되지 않아 적은 예시만으로 채점해요. 연결하면 튜터가 숨은 테스트를 만들어 줘요."다.
- 빠진 것이 있으면 그 칸 아래에 알린다. 글이 없으면 "문제 글을 붙여 넣거나 파일을 넣어 주세요.", 제목이 없으면 "제목을 적어 주세요.", 예시가 없으면 케이스 칸을 열고 "테스트 케이스를 하나 이상 적어 주세요."가 뜬다.
- '새로 쓰기'는 적은 제목, 글, 케이스, 파일을 모두 지운다. 지우기 전에 확인을 받는다.
- 적던 글과 채운 칸, 고친 칸은 초안으로 이 탭의 브라우저 저장소(sessionStorage)에만 둔다. 새로고침해도 남고, 탭을 닫거나 등록하거나 '새로 쓰기'를 누르면 지운다.

## 받는 입력

- 붙여 넣기: 문제 설명, 제한사항, 입출력 예를 그대로 붙여 넣는다.
- 웹 페이지에서 복사한 글: 붙여 넣을 때 HTML을 글로 바꾼다. HTML은 글을 뽑는 데만 쓰고 화면에 넣지 않는다.
  - 빼는 것: 메뉴(`nav`), 쪽의 머리글과 바닥글(`header`, `footer`. 본문 안의 것은 남긴다), 옆 칸(`aside`), 입력 양식(`form`)과 단추, 스크립트와 스타일, 그림, 숨긴 요소, 같은 역할(`navigation`, `banner`, `contentinfo`, `complementary`, `search`)의 요소.
  - 바꾸는 것: 위첨자(`<sup>`)는 `^`, 아래첨자(`<sub>`)는 `_`로 바꾼다. 그래서 `10<sup>5</sup>`는 `10^5`가 된다. TeX 원문이 달린 수식은 `$…$`로 바꾸고, TeX가 없는 MathML의 위·아래 첨자도 `^`, `_`로 바꾼다. 표의 칸은 탭으로 나눈다.
  - 바꾼 글이 글만 복사한 것의 절반보다 짧으면 바꾸지 않고 그대로 붙인다.
- 파일: '파일에서 가져오기'로 고르거나 끌어다 놓는다.
- 받는 형식은 png, jpg, jpeg, webp, gif, pdf, md, txt다.
- 파일 하나는 8MB까지, 이미지는 20장까지, PDF는 한 개까지 올린다.
- 이름과 크기가 같은 파일은 다시 받지 않는다. 올린 파일은 하나씩 '빼기'로 뺄 수 있다.
- md와 txt는 UTF-8(BOM 포함)으로 읽고, 안 되면 CP949로 읽는다.
- PDF는 글을 뽑아 읽는다. 글이 없는 스캔 PDF는 "<파일 이름>에서 글을 찾지 못했습니다. 이미지로 올려 주세요."라고 알린다.
- 글 파일(md·txt·pdf)만 올렸고 글 칸이 비어 있으면 바로 읽는다. 사진이 섞이면 '글 읽어 오기' 단추로 읽는다. 읽지 않은 파일이 있는 채로 등록을 누르면 먼저 읽고 멈춘다. 채운 것을 본 뒤 다시 누른다.
- 직접 적은 글은 읽어 온 글 앞에 이어 붙는다. 읽은 뒤에는 "읽어 온 글이에요. 틀린 곳이 없는지 확인하고 고쳐 주세요."가 뜨고, 읽은 글로 제목과 예시를 채운다.
- 올린 원본은 등록할 때 데이터 폴더에 보관한다.

## 이미지 읽기

- AI가 연결돼 있으면 모델이 이미지를 읽는다. 한 장을 두 번 못 읽으면 그 장만 이 기기의 글자 읽기로 읽는다.
- AI가 없으면 이 기기의 글자 읽기(tesseract)로 읽는다. tesseract가 기기에 설치돼 있어야 한다. 없거나 10초 안에 끝나지 않으면 그 장의 글을 믿지 못하는 것으로 본다.
- tesseract 결과는 공백을 뺀 20자 이상이고 이상한 글자가 10% 이하일 때만 믿는다. 믿지 못하고 AI도 없으면 "이미지에서 글을 읽으려면 AI를 연결해야 해요. 연결하거나, 글을 직접 붙여 넣어 주세요."가 뜬다. AI가 있는데도 못 읽은 장이면 "n번째 장을 읽지 못했습니다."가 뜬다.
- 글자 읽기로 읽은 글에는 "이 기기의 글자 읽기로 읽었어요. 틀린 글자가 많을 수 있으니 원본과 견줘 고쳐 주세요. AI를 연결하면 더 정확하게 읽어요."가 붙는다.
- 읽은 글을 모델 없이 대조한다. 입출력 예와 제한사항의 수 범위를 찾았는지 보고, AI가 읽은 장의 숫자를 글자 읽기의 숫자와 견준다(양쪽에 서로 없는 수가 있으면 어긋난 것으로 본다).
- 어긋난 곳이 있으면 AI가 읽은 장 하나를 한 번 다시 읽는다. 그래도 남은 곳은 "확인이 필요한 곳 n개"로 글 칸 위에 보인다.
- 읽기만 하고 저장하지 않는다. 등록 전에 직접 고친다.

## 제목과 예시를 채우는 규칙

화면은 `/api/problems/detect` 요청으로 글을 읽는다. 저장하지 않는다. 글이 바뀌면 0.25초 뒤에 규칙만으로(`fast: true`, 모델 0회) 읽어 칸을 채운다. AI가 연결돼 있으면 0.8초 뒤에 같은 글을 한 번 더 보내 모델이 한 번 더 읽는다. 같은 글은 모델에게 다시 보내지 않는다. 수정 화면은 모델을 부르지 않고 규칙으로만 다시 읽는다. 칸은 덮지 않고 미리보기의 구역만 나눈다.

- 읽기 전에 줄마다 글을 고른다. NBSP와 전각 공백은 빈칸으로 바꾸고, 폭 없는 글자는 지우고, 전각 영문·숫자·기호와 빼기 기호(−)는 보통 글자로 바꾼다. `10⁵` 같은 위 첨자는 그대로 둔다. 줄은 `\r\n`, `\r`, `\n`과 그 밖의 줄 나눔 글자(`\v`, `\f`, U+001C~U+001E, U+0085, U+2028, U+2029)에서 나누고(파이썬 `str.splitlines`), 줄 번호는 그렇게 나눈 보낸 글의 줄이다.
- 구역: 구역 머리 줄(문제·문제 설명·참고, 제한사항·제약, 입력, 출력, 입출력 예·예제·예시, 영문 Problem·Constraints·Input·Output·Sample 등. 앞의 `#`와 끝의 쌍점은 뗀다)로 줄마다 구역을 정한다. '문제' 칸은 제목 줄, 입출력 예 구역, 문제 밖 줄을 뺀 나머지를 보인다.
- 제목: 머리를 건너뛴 첫 줄이 `#` 제목이거나 40자 이하이고 문장이 아니면(`.`·`?`로 끝나거나 '입니다·합니다·주어집니다'로 끝나지 않으면) 그 줄이다. 제목을 고치지 않고 등록하면 본문에서 그 줄을 뺀다.
- 함수 방식의 예시: 머리의 마지막 칸이 result, return, answer, 결과, 반환, 출력인 첫 표를 쓴다. 나머지 칸은 인자 이름이 된다. 칸 값은 JSON으로 읽고, 안 되면 파이썬식(True·False·None, 작은따옴표, 끝 쉼표)으로 읽는다. 따옴표 없는 낱말은 글로 짐작하지 않는다.
- 표준 입출력 방식의 예시: "예제 입력 N"과 "예제 출력 N" 짝을 쓴다. "입력 예 N"·"출력 예 N"과 "Sample Input N"·"Sample Output N"도 된다.
- 방식: 표에서 예시를 찾으면 함수 방식, 예제 구역에서만 찾으면 표준 입출력 방식, 둘 다 없으면 함수 방식이다. '더 정하기'에서 방식을 고르면 그 방식으로 다시 읽는다.
- 수 범위(`≤`, `<=`, `이상`, `이하`, TeX의 `\le` 등)는 제한·입력 구역의 줄에서 찾는다.
- 다 읽지 못하면 '입출력 예' 칸에 알린다. 함수 방식은 "표의 n줄은 읽지 못했어요.", 표 뒤에 예시처럼 보이는 줄이 남으면 "예시처럼 보이는 줄 n개를 읽지 못했어요.", 표준 입출력은 "예제 n개는 출력을 찾지 못해 넣지 않았어요."다. 예제 출력 안에 빈 줄이 있고 그 뒤로 글이 더 있으면 "예시 n의 기대 출력에 빈 줄 뒤로 글이 더 있어요. 출력이 아닌 글이 섞였는지 확인해 주세요."라고 알린다.
- 예시를 하나도 찾지 못하면 감지 줄에 "입출력 예를 찾지 못했어요. ‘입출력 예’ 칸에 직접 넣어 주세요"가 뜬다.

### 모델이 보태는 것

- '문제 나누기' 과정의 모델(기본 작음·low)에게 줄 번호를 붙인 글을 주고 줄 위치만 받는다. 모델이 쓴 글은 문제 글이나 케이스에 넣지 않는다. 표와 예제 구역은 모델이 짚은 줄을 규칙으로 읽는다. 문장으로 적힌 함수 예시는 값마다 그 줄에 글자 그대로 있고 칸 값으로 읽혀야 쓴다. 모델이 준 인자 이름은 모두 식별자 꼴(영문자·숫자·밑줄)이고 글에 낱말로 글자 그대로 있을 때만 쓰고, 하나라도 아니면 비운다. 글이 40,000자를 넘으면 모델에게 보내지 않는다.
- 호출이 실패하거나 모델 답이 검사에 걸리면(글 밖의 줄, 거꾸로 되거나 겹친 구간, 잡음 안의 제목 줄, 전체의 60%를 넘는 잡음, 맞지 않는 모양) 가운데 급으로 한 번 더 묻고, 그래도 안 되면 규칙 결과를 그대로 쓴다. 공급자 연결은 모양이 깨진 답(JSON이 아니거나 키가 빠짐)을 한 번 더 요청하므로 한 번 감지에 요청이 4번까지 갈 수 있다.
- 합치는 차례: 규칙이 예시를 빠짐없이 읽었으면(읽지 못한 줄도 넘친 글도 없으면) 규칙의 예시와 방식을 쓴다. 모델은 제목, 문제 밖 줄, 규칙이 비웠거나 다 읽지 못한 예시, 예시가 없을 때의 방식을 채운다. 표준 입출력 문제에서 모델이 답이 여럿일 수 있다고 보면 '답이 여럿일 수 있음'을 켠다. 끌 수 있다. 규칙만으로는 켜지 않는다.
- 문제 밖 줄: 모델이 문제 밖으로 본 줄(메뉴, 댓글, 광고 같은 것)은 두 칸에서 빼고 감지 줄에 "문제 밖 글 n줄을 뺐어요"가 뜬다. 규칙만으로는 문제 밖 줄을 찾지 않는다.
- 등록하거나 수정해 저장할 때 그 줄을 문제 글에서 빼고 저장한다. '문제 글' 칸의 글은 그대로 둔다.
- '보기'를 누르면 뺀 줄이 줄마다 '되돌리기' 단추와 함께 보인다. 되돌린 줄은 미리보기와 저장하는 글에 그대로 들어간다. '다시 빼기'로 다시 뺄 수 있다. 남긴 줄은 글을 고쳐 다시 감지해도 남는다. 모두 남기면 감지 줄에 "문제 밖으로 본 줄을 모두 남겼어요"가 뜬다.
- 수정 화면도 같은 규칙이다. 다만 수정 화면은 모델을 부르지 않으므로 규칙 감지로는 문제 밖 줄이 나오지 않는다.

### 고친 칸은 덮지 않는다

- 제목, 입출력 방식, 케이스, '답이 여럿일 수 있음'을 손으로 고치면 그 칸은 고친 칸이 된다. 뒤에 오는 감지는 고친 칸을 덮지 않는다. 케이스를 고쳤으면 방식도 그대로 둔다.
- 감지 요청은 고친 칸을 `touched`로 보낸다. 서버는 그 칸을 규칙 결과 그대로 두고 모델이 다르게 본 값을 `suggest`에 싣는다. `touched`에 `mode`가 있으면 요청의 `mode`로 예시를 읽는다.
- 모델이 고친 칸을 다르게 봤으면 감지 줄에 "AI는 다르게 읽었어요: …"와 'AI가 읽은 대로 바꾸기' 단추가 뜬다. 누르면 그 칸을 바꾸고 다시 감지가 채우는 칸으로 돌린다.

### 문제 글로 보이지 않을 때

- 모델이 문제 글이 아니라고 봤거나, 예시도 문제 밖이 아닌 줄의 수 범위도 없으면 감지 줄에 "문제 글로 보이지 않아요. 그래도 등록할 수 있어요."가 뜬다. 등록은 막지 않는다.
- 이 경고가 뜬 채 등록하면 요청에 `problem: false`를 함께 보낸다. 서버는 등록하되 뒤에서 준비하지 않는다. 문제를 열어도 준비하지 않고, 상태의 `hold`가 참이다.
- AI가 연결돼 있으면 문제 머리에 "문제 글로 보이지 않아 풀이 준비를 미뤘어요"와 '준비 시작' 단추가 뜬다. 누르면 `/api/problems/prepare`를 보내 준비를 시작한다.

### 응답 칸

`problem`, `notice`, `title`, `mode`, `names`, `cases`, `skipped`, `kinds`(줄마다 `title`·`body`·`limits`·`input`·`output`·`sample`·`noise`·빈 글), `bounds`(수 범위가 있는 줄, 보낸 글 그대로), `many`, `suggest`. 표·예제 읽기가 알릴 것이 있으면 `missed`, `spill`이 붙는다.

## 케이스 칸과 검사

- 함수 방식의 '넣을 값'은 인자를 순서대로 대괄호 안에 적는다. 예: `[[1, 2, 3], 5]`. 아래에 `→ solution(…)` 호출 모양이 미리 보인다.
- 표준 입출력 방식은 입력과 기대 출력을 글 그대로 적는다. 각각 20,000자까지이고, 기대 출력은 필수다.
- 케이스마다 '숨김'을 켜면 숨은 테스트가 된다. 제출할 때만 돌고 통과 여부만 보인다.
- 공개 예시가 하나는 있어야 한다.
- 제목은 80자까지다. 문제 글은 필수다.
- 함수 방식은 케이스끼리 인자 수가 같아야 하고, 같은 자리의 값 형이 어울려야 한다. 정수와 실수는 어울린다. 한 목록에 다른 종류의 값을 섞을 수 없다. null은 된다. NaN과 Infinity는 받지 않는다.
- 함수 방식은 실수를 0.000001 차이까지 같게 본다. 표준 입출력은 줄 끝 공백과 끝의 빈 줄만 빼고 글자 그대로 본다. 표준 입출력 문제에서 '입출력 예' 칸의 '실수 답'을 켜면 기대 출력에 소수로 적힌 값을 0.000001 차이까지 같게 보고, '답이 여럿일 수 있음'을 켜면 다른 답은 가릴 수 없다고 알리고 숨은 테스트를 만들지 않는다. 둘 다 수정에서 바꿀 수 있다.
- 효율성 케이스는 직접 넣을 수 없다. 대조가 만든다(아래 '검증 표시').

## 더 정하기

'더 정하기'에서 네 가지를 정한다. 주제와 단계는 '정하지 않음'으로 두면 자동으로 정한다.

- 언어: 다섯 언어 가운데 하나다. 기본은 python이다. 등록한 뒤에는 코드 화면에서 바꾼다.
- 입출력 방식: '함수(solution)' 또는 '표준 입출력'이다. 등록한 뒤에는 바꿀 수 없다.
- 주제: 15개 주제 가운데 하나 또는 '정하지 않음'이다. 정하지 않으면 튜터 계획이 고른 알고리즘이 15개 주제 안일 때 그것을 보여 주되 저장하지 않는다.
- 단계: '1단계'부터 '5단계'까지 또는 '정하지 않음'이다. 정하지 않으면 분석이 붙인 단계를 쓴다.

분석이 붙인 기법 이름은 태그 칩으로 보인다. 함수 방식의 시작 코드는 케이스 값의 형으로 만든다. 형을 정하지 못하면 "케이스에서 타입을 정하지 못해 시작 코드를 만들지 못했어요."가 뜬다.

## 검증 표시

등록한 뒤 튜터는 두 걸음으로 준비한다. 1걸음은 뼈대, 풀이 가이드, 블록을 만든다. 그동안 문제 머리에 '풀이 준비 중'이 보이고, 끝나면 튜터와 바로 풀기 시작할 수 있다. 2걸음은 가이드를 대조해 케이스를 만든다. 그동안 문제 머리에 '숨은 테스트 만드는 중'이 보이고, 튜터와 푸는 것을 막지 않는다. 대조는 모델이 쓴 정답 풀이와 단순한 풀이를 케이스 생성기가 만든 입력에서 채점기로 견준다. 결과가 같은 입력은 숨은 케이스(최대 20개)가 된다. 대조가 맞으면 생성기의 큰 입력을 정답 풀이로 돌려 효율성 케이스(최대 3개)를 만든다.

| 표시 | 뜻 |
|---|---|
| 예시와 자동 테스트 모두 통과 (`all`) | 예시와 대조를 모두 통과했다 |
| 예시만 통과 (`examples`) | 대조하지 못했다. 예시만 통과했다 |
| 검증하지 못함 (`none`) | 검증하지 못했다. 예시를 통과하는 풀이를 얻지 못했거나 대조 결과가 달랐다 |

- 대조 결과가 같으면 `all`, 다르면 `none`, 하지 못했으면 `examples`다.
- `none`이면 까닭과 예시 번호를 남긴다.
- 대조에서 다시 푼 풀이로 가이드가 바뀌면 블록을 새 가이드로 다시 짠다. 이미 튜터와 풀기 시작했으면(대화, 해설, 블록 진행, 블록 칸의 코드) 바꾸지 않고 문제 머리에 "튜터의 풀이를 더 정확한 것으로 바꿀 수 있어요"와 '다시 준비' 단추를 띄운다. 누르면 튜터와 나눈 대화(꼬리질문과 디버그 대화도), 해설, 블록 진행, 블록 칸의 코드, 디버그 상태를 지우고 새 가이드로 다시 준비한다. 코드 칸의 코드, 다른 언어로 쓰던 코드, 제출 기록, 체크포인트, 피드백은 남는다.
- 2걸음이 끝나기 전에 앱을 끄면 다음에 그 문제를 열 때 대조한다.
- 기본 문제는 늘 `all`이다.
- 효율성 제한은 정답 풀이가 걸린 시간에서 정한다. 배수는 8이고, 바닥은 1초이며, 언어마다 상한이 있다.

## 모델이 필요한 것

- 모델 없이 되는 것: 붙여 넣기(웹 페이지 글 바꾸기 포함), md·txt·PDF 읽기, 규칙으로 제목·방식·예시 채우기, 두 칸 미리보기, 모양 검사, 등록, 시작 코드 만들기, 예시만으로 채점.
- 모델이 필요한 것: 이미지 읽기(없으면 글자 읽기로 대신), 글 감지의 모델 보탬(없으면 규칙만), 풀이 가이드·블록·힌트 만들기, 숨은 케이스와 효율성 케이스 만들기(대조), 단계와 태그 분석, 등록한 문제의 해설.
- 연결이 없으면 등록해도 뒤에서 준비를 시작하지 않는다.

## 수정과 삭제

- '더 보기'의 '문제 수정'과 '문제 삭제'로 등록한 문제를 바꾸거나 지운다. 기본 문제는 고치거나 지울 수 없다.
- 글이나 케이스를 바꾸면 "문제 글이나 케이스를 바꾸면 튜터와 나눈 대화와 블록 진행이 지워져요. 제출 기록과 코드는 남아요."라는 확인이 뜬다.
- 제목이나 주제만 바꾸면 준비를 그대로 둔다. 케이스만 바꾸면 가이드 코드를 새 케이스로 채점해 통과하면 그대로 두고, 아니면 다시 만든다. 글을 바꾸면 준비를 지우고 다시 만든다.
- 삭제하면 문제, 풀이 기록, 블록과 언어별 코드, 체크포인트, 원본 파일, 대조로 만든 효율성 케이스, 검색 색인 항목을 모두 지운다. 되돌릴 수 없다.

## 알려진 한계

- bmp 파일은 받지 않는다.
- 이미지 읽기를 AI 없이 하면 글자 읽기로 읽게 되고, 틀린 글자가 많을 수 있다.
- 등록 문제의 풀이 준비, 숨은 케이스, 해설은 AI 연결이 있어야 한다.
