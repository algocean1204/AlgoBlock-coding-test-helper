# 내 문제 넣기

이 문서는 가진 문제를 글이나 사진으로 넣어 등록하는 세 걸음, 받는 입력과 한계, 예시 표에서 케이스를 채우는 법, 검증 표시, 모델이 필요한 부분을 설명한다.

## 세 걸음

'내 문제 넣기' 화면은 '1 글 넣기' → '2 확인하기' → '3 등록' 세 걸음이다. '이전'과 '다음'으로 오간다. 마지막 단추는 '등록하고 풀러 가기'다.

1. 글 넣기: 문제 글을 붙여 넣거나 파일을 올린다. '다음'을 누르면 올린 파일을 읽는다. 제목이 비어 있으면 글의 첫 줄이 제목 모양(40자 이하이고 문장이 아님)일 때 그 줄로 채운다. 케이스가 없으면 예시 표에서 채운다. 글이 비어 있으면 "문제 글을 붙여 넣거나 파일을 넣어 주세요."가 뜬다.
2. 확인하기: 읽은 글과 예시를 고친다. 제목과 케이스 하나 이상이 있어야 '다음'을 누를 수 있다.
3. 등록: 제목, 예시 수, 푸는 방식, 주제와 단계를 확인하고 등록한다. 같은 글을 이미 넣었으면 먼저 알리고, 한 번 더 누르면 넣는다. 숨은 케이스 수는 준비가 끝난 뒤 문제 머리에 보인다. 등록하면 그 문제의 풀이 화면으로 바로 간다.

- 연결돼 있으면 "등록하면 튜터가 풀이와 숨은 테스트를 준비해요. 모델을 쓰고 1분 안팎 걸려요. 그동안 문제를 읽고 풀기 시작해도 돼요."가 뜬다.
- 연결이 없으면 "AI가 연결되지 않아 적은 예시만으로 채점해요. 연결하면 튜터가 숨은 테스트를 만들어 줘요."가 뜬다.
- '새로 쓰기'는 적은 제목, 글, 케이스, 파일을 모두 지운다. 지우기 전에 확인을 받는다.

## 받는 입력

- 붙여 넣기: 문제 설명, 제한사항, 입출력 예를 그대로 붙여 넣는다.
- 파일: '파일에서 가져오기'로 고르거나 끌어다 놓는다.
- 받는 형식은 png, jpg, jpeg, webp, gif, pdf, md, txt다.
- 파일 하나는 8MB까지, 이미지는 20장까지, PDF는 한 개까지 올린다.
- 이름과 크기가 같은 파일은 다시 받지 않는다. 올린 파일은 하나씩 '빼기'로 뺄 수 있다.
- md와 txt는 UTF-8(BOM 포함)으로 읽고, 안 되면 CP949로 읽는다.
- PDF는 글을 뽑아 읽는다. 글이 없는 스캔 PDF는 "<파일 이름>에서 글을 찾지 못했습니다. 이미지로 올려 주세요."라고 알린다.
- 글 파일(md·txt·pdf)만 올렸고 글 칸이 비어 있으면 바로 읽는다. 사진이 섞이면 '글 읽어 오기' 단추나 '다음'으로 읽는다.
- 직접 적은 글은 읽어 온 글 앞에 이어 붙는다. 읽은 뒤에는 "읽어 온 글이에요. 틀린 곳이 없는지 확인하고 고쳐 주세요."가 뜬다.
- 올린 원본은 등록할 때 데이터 폴더에 보관한다.

## 이미지 읽기

- AI가 연결돼 있으면 모델이 이미지를 읽는다. 한 장을 두 번 못 읽으면 그 장만 이 기기의 글자 읽기로 읽는다.
- AI가 없으면 이 기기의 글자 읽기(tesseract)로 읽는다. tesseract가 기기에 설치돼 있어야 한다. 없거나 10초 안에 끝나지 않으면 그 장의 글을 믿지 못하는 것으로 본다.
- tesseract 결과는 공백을 뺀 20자 이상이고 이상한 글자가 10% 이하일 때만 믿는다. 믿지 못하고 AI도 없으면 "이미지에서 글을 읽으려면 AI를 연결해야 해요. 연결하거나, 글을 직접 붙여 넣어 주세요."가 뜬다. AI가 있는데도 못 읽은 장이면 "n번째 장을 읽지 못했습니다."가 뜬다.
- 글자 읽기로 읽은 글에는 "이 기기의 글자 읽기로 읽었어요. 틀린 글자가 많을 수 있으니 원본과 견줘 고쳐 주세요. AI를 연결하면 더 정확하게 읽어요."가 붙는다.
- 읽은 글을 모델 없이 대조한다. 입출력 예와 제한사항의 수 범위를 찾았는지 보고, AI가 읽은 장의 숫자를 글자 읽기의 숫자와 견준다(양쪽에 서로 없는 수가 있으면 어긋난 것으로 본다).
- 어긋난 곳이 있으면 AI가 읽은 장 하나를 한 번 다시 읽는다. 그래도 남은 곳은 "확인이 필요한 곳 n개"로 글 칸 위에 보인다.
- 읽기만 하고 저장하지 않는다. 등록 전에 직접 고친다.

## 예시 표에서 케이스 채우기

- 글에 입출력 예 표가 있으면 '입출력 예에서 채우기' 단추가 뜬다. 모델을 쓰지 않는다.
- 글에서 입출력 예를 찾지 못하면 "글에서 입출력 예를 찾지 못했어요. 아래에 직접 넣어 주세요."라고 알린다. 문장으로만 적힌 예시는 읽지 못한다.
- 함수 방식은 머리의 마지막 칸이 result, return, answer, 결과, 반환, 출력인 첫 표를 쓴다. 나머지 칸은 인자 이름이 된다.
- 표준 입출력 방식은 "예제 입력 N"과 "예제 출력 N" 짝을 쓴다. "입력 예 N"·"출력 예 N"과 "Sample Input N"·"Sample Output N"도 된다.
- 칸 값은 JSON으로 읽는다. 안 되면 파이썬식(True·False·None, 작은따옴표, 끝 쉼표)으로 읽는다. 따옴표 없는 낱말은 글로 짐작하지 않는다.
- 함수 방식에서 읽지 못한 줄은 "표의 n줄은 읽지 못했어요. 직접 넣어 주세요."로 알린다.
- 이미 적은 케이스가 있으면 "지금 적힌 케이스를 표의 것으로 바꿀까요?"라고 묻는다.
- 찾은 케이스가 다른 방식(함수 ↔ 표준 입출력)의 꼴이면 방식을 자동으로 바꾸지 않는다. "함수(solution) 문제처럼 보여요." 같은 알림 한 줄과 '함수로 바꾸기' 또는 '표준 입출력으로 바꾸기' 단추로 묻는다. 수정 화면에서는 묻지 않는다.
- 예제 출력 안에 빈 줄이 있고 그 뒤로 글이 더 있으면 "예시 n의 기대 출력에 빈 줄 뒤로 글이 더 있어요. 출력이 아닌 글이 섞였는지 확인해 주세요."라고 알린다.

## 케이스 칸과 검사

- 함수 방식의 '넣을 값'은 인자를 순서대로 대괄호 안에 적는다. 예: `[[1, 2, 3], 5]`. 아래에 `→ solution(…)` 호출 모양이 미리 보인다.
- 표준 입출력 방식은 입력과 기대 출력을 글 그대로 적는다. 각각 20,000자까지이고, 기대 출력은 필수다.
- 케이스마다 '숨김'을 켜면 숨은 테스트가 된다. 제출할 때만 돌고 통과 여부만 보인다.
- 공개 예시가 하나는 있어야 한다.
- 제목은 80자까지다. 문제 글은 필수다.
- 함수 방식은 케이스끼리 인자 수가 같아야 하고, 같은 자리의 값 형이 어울려야 한다. 정수와 실수는 어울린다. 한 목록에 다른 종류의 값을 섞을 수 없다. null은 된다. NaN과 Infinity는 받지 않는다.
- 함수 방식은 실수를 0.000001 차이까지 같게 본다. 표준 입출력은 줄 끝 공백과 끝의 빈 줄만 빼고 글자 그대로 본다. 표준 입출력 문제에서 2 확인하기의 '실수 답'을 켜면 기대 출력에 소수로 적힌 값을 0.000001 차이까지 같게 보고, '답이 여럿일 수 있음'을 켜면 다른 답은 가릴 수 없다고 알리고 숨은 테스트를 만들지 않는다. 둘 다 수정에서 바꿀 수 있다.
- 효율성 케이스는 직접 넣을 수 없다. 대조가 만든다(아래 '검증 표시').

## 더 정하기

'더 정하기'에서 네 가지를 정한다. 주제와 단계는 '정하지 않음'으로 두면 자동으로 정한다.

- 언어: 일곱 언어 가운데 하나다. 기본은 python이다. 등록한 뒤에는 코드 화면에서 바꾼다.
- 푸는 방식: '함수(solution)' 또는 '표준 입출력'이다. 등록한 뒤에는 바꿀 수 없다.
- 주제: 15개 주제 가운데 하나 또는 '정하지 않음'이다. 정하지 않으면 튜터 계획이 고른 알고리즘이 15개 주제 안일 때 그것을 보여 주되 저장하지 않는다.
- 단계: '1단계'부터 '5단계'까지 또는 '정하지 않음'이다. 정하지 않으면 분석이 어림한 단계를 쓰고 "n단계 · 어림"으로 표시한다.

분석이 붙인 기법 이름은 태그 칩으로 보인다. 함수 방식의 시작 코드는 케이스 값의 형으로 만든다. 형을 정하지 못하면 "케이스에서 타입을 정하지 못해 시작 코드를 만들지 못했어요."가 뜬다.

## 검증 표시

등록한 뒤 튜터가 풀이를 준비할 때 대조로 케이스를 확인한다. 대조는 모델이 쓴 정답 풀이와 단순한 풀이를 케이스 생성기가 만든 입력에서 채점기로 견준다. 결과가 같은 입력은 숨은 케이스(최대 20개)가 된다. 대조가 맞으면 생성기의 큰 입력을 정답 풀이로 돌려 효율성 케이스(최대 3개)를 만든다.

| 표시 | 뜻 |
|---|---|
| 예시와 자동 테스트 모두 통과 (`all`) | 예시와 대조를 모두 통과했다 |
| 예시만 통과 (`examples`) | 대조하지 못했다. 예시만 통과했다 |
| 검증하지 못함 (`none`) | 검증하지 못했다. 예시를 통과하는 풀이를 얻지 못했거나 대조 결과가 달랐다 |

- 대조 결과가 같으면 `all`, 다르면 `none`, 하지 못했으면 `examples`다.
- `none`이면 까닭과 예시 번호를 남긴다.
- 기본 문제는 늘 `all`이다.
- 효율성 제한은 정답 풀이가 걸린 시간에서 정한다. 배수는 8이고, 바닥은 1초이며, 언어마다 상한이 있다.

## 모델이 필요한 것

- 모델 없이 되는 것: 붙여 넣기, md·txt·PDF 읽기, 예시 표에서 케이스 채우기, 모양 검사, 등록, 시작 코드 만들기, 예시만으로 채점.
- 모델이 필요한 것: 이미지 읽기(없으면 글자 읽기로 대신), 풀이 가이드·블록·힌트 만들기, 숨은 케이스와 효율성 케이스 만들기(대조), 단계와 태그 분석, 등록한 문제의 해설.
- 연결이 없으면 등록해도 뒤에서 준비를 시작하지 않는다.

## 수정과 삭제

- '더 보기'의 '문제 수정'과 '문제 삭제'로 등록한 문제를 바꾸거나 지운다. 기본 문제는 고치거나 지울 수 없다.
- 글이나 케이스를 바꾸면 "문제 글이나 케이스를 바꾸면 튜터와 나눈 대화와 블록 진행이 지워져요. 제출 기록과 코드는 남아요."라는 확인이 뜬다.
- 제목이나 주제만 바꾸면 준비를 그대로 둔다. 케이스만 바꾸면 가이드 코드를 새 케이스로 채점해 통과하면 그대로 두고, 아니면 다시 만든다. 글을 바꾸면 준비를 지우고 다시 만든다.
- 삭제하면 문제, 풀이 기록, 블록과 언어별 코드, 체크포인트, 원본 파일, 대조로 만든 효율성 케이스, 검색 색인 항목을 모두 지운다. 되돌릴 수 없다.

## 알려진 한계

- bmp 파일은 받지 않는다.
- 이미지 읽기를 AI 없이 하면 글자 읽기로 읽게 되고, 틀린 글자가 많을 수 있다.
- 등록 문제의 풀이 준비, 숨은 케이스, 해설은 AI 연결이 있어야 한다.
