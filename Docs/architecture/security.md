# 보안

이 문서는 로컬 서버의 요청 검사, 키 다루기, 모델이 만든 코드가 도는 곳, 업데이트, 알려진 한계를 설명한다. 보안 문제를 알리는 방법은 [SECURITY.md](../../.github/SECURITY.md)를 본다.

## 로컬 서버 요청 검사

서버는 `127.0.0.1`에만 묶인다. 포트만 `ALGOBLOCK_UI_PORT`로 바꿀 수 있다.

- Host: GET과 POST 모두 호스트 부분이 `127.0.0.1` 또는 `localhost`여야 한다. 아니면 403이다. DNS 되묶기를 막는다.
- POST는 본문을 읽기 전에 검사한다.
- Content-Type: 미디어 타입이 정확히 `application/json`이어야 한다. 아니면 415다.
- Origin: 있으면 `http://127.0.0.1:<포트>` 또는 `http://localhost:<포트>`만 허용한다. 아니면 403이다.
- Sec-Fetch-Site: 있으면 `same-origin` 또는 `none`만 허용한다. 아니면 403이다.
- Content-Length가 숫자가 아니면(음수 포함) 400이다.
- GET과 POST 밖의 방식(PUT, DELETE, PATCH, OPTIONS, TRACE, CONNECT)은 405다.
- 깨진 JSON, 너무 깊은 중첩, 객체가 아닌 본문은 400이다.
- 코드 요청은 글이어야 하고, NUL과 짝 없는 서로게이트를 거절한다.
- 처리 중 예외는 500과 일반 문구로 답한다. 예외의 자취는 표준 오류에만 쓴다.
- 기본 HTTP 접근 로그는 끈다. POST마다 경로, 상태, 걸린 시간만 표준 오류에 쓴다(개발용 CLI 연결이면 모델 호출 수도). 본문은 쓰지 않는다.
- 모든 응답에 `Cache-Control: no-store`를 붙인다.

## 본문 상한과 올린 파일

- 본문 상한은 일반 요청 1,000,000바이트다. 파일을 싣는 `/api/problems/read`, `/new`, `/edit`만 60,000,000바이트다. 넘으면 413이다.
- 올린 파일 하나는 디코드한 뒤 8MB까지다. 형식은 png, jpg, jpeg, webp, gif, pdf, md, txt만 받는다.
- 원본 응답에는 `X-Content-Type-Options: nosniff`와 `Content-Disposition: inline`을 붙인다. md와 txt는 `text/plain`으로 준다. HTML로 읽히지 않게 하려는 것이다.
- 원본 파일 이름은 서버가 붙인 번호(`NN.<확장자>`)다. 사용자가 붙인 이름은 경로에 쓰지 않는다.
- 등록 문제의 id는 서버가 `u`와 uuid 8자리로 만든다.

## 경로 검사

- GET은 정해 둔 정적 파일 목록과 올린 원본만 낸다.
- 원본 경로는 정규식으로만 받는다. `/asset/u<8자리 16진수>/<1–2자리 숫자>` 꼴이어야 하고, 번호와 형식은 `index.json`에 적힌 것만 허용한다.
- 화면은 사용자와 모델의 글을 이스케이프해서 HTML에 넣는다.

## 키 다루기

- 키는 `keys.json`(권한 0600), `.env`, 또는 환경 변수에 둔다. 화면에서 넣은 키는 `keys.json`에 저장된다. Windows에는 권한 비트가 없어 0600이 적용되지 않는다. 대신 키와 로그인 토큰 파일은 데이터 폴더(설치 파일은 사용자 프로필 아래의 `%APPDATA%\AlgoBlock`) 안에만 두고, 그 폴더의 기본 권한에 기댄다.
- 화면 응답은 키 값이 아니라 키가 있는지만 알려 준다. 키 입력 칸은 password 형식이다.
- 키는 공급자 요청 머리(`x-api-key`, `Authorization: Bearer`)로만 나간다.
- 공급자 오류 문구에는 상태 코드만 싣는다.
- 사용량 기록(`usage.jsonl`)에는 키와 프롬프트 글을 적지 않는다. 측정용 프롬프트 사본에도 키가 없다. 사본은 기본으로 꺼져 있다.
- 소스 실행의 데이터 폴더(`app/ui/data`)는 그 안의 `.gitignore`로 git에서 빠진다([데이터 폴더](data.md)).
- ChatGPT 로그인: 콜백 리스너는 기본으로 `127.0.0.1:1455`에 열린다(쓰고 있으면 빈 포트). 콜백 경로만 받고 나머지는 404다. 로그인마다 state·nonce와 PKCE(S256)를 새로 만들고, state가 다르면 무시하고 리스너는 그대로 둔다. ID 토큰은 OpenAI가 공개한 키(JWKS)로 서명을 검증한다. 콜백을 한 번 받거나 300초가 지나면 닫는다. 토큰 파일은 임시 파일에 쓴 뒤 바꿔 끼우고, 권한 0600으로 만든다.

## 모델이 만든 코드가 도는 곳

모델이 만든 코드는 모두 채점기의 하위 프로세스에서 돈다. 서버 프로세스 안에서 실행하지 않는다.

- 풀이 가이드의 정답 코드: 그 문제에 있는 케이스(공개 예시, 숨은 케이스, 효율성 케이스)로 채점기에서 돈다.
- 블록 코드 확인: 가이드 코드에 내 블록을 끼운 프로그램을 채점기에서 돈다. 효율성 케이스는 빼고, 시간 초과가 한 번이면 멈춘다.
- 등록 문제의 대조: 모델이 쓴 정답 풀이, 단순 풀이(Python), 케이스 생성기(Python)를 모두 채점기 프로세스로만 돌린다. 생성기가 낸 입력은 생성기가 적은 범위와 모양을 규칙으로 다시 검사한다.
- 대조 실행 제한: 작은 입력 5초, 생성기 20초, 큰 입력은 그 언어의 상한을 쓴다.
- 서버 프로세스 안에서 `exec`로 실행하는 것은 기본 문제에 실린 `gen.py`(저장소의 소스)뿐이다.
- OCR: tesseract를 하위 프로세스로 10초 제한을 두고 부른다.

OCR을 뺀 위 실행은 모두 채점기를 거치므로 채점기의 시간·출력·메모리·CPU 제한과 환경 변수 거르기를 받는다. Windows에서는 동시 프로세스 수 상한(64개)과 오류 창 끄기도 받는다. 그 값은 [채점기](judge.md#시간과-메모리)와 [실행 환경](judge.md#실행-환경)에 있다.

## 격리 없음

제출 코드와 모델이 만든 코드 모두 격리되지 않는다. 컨테이너나 OS 샌드박스를 쓰지 않는다. 사용자 권한으로, 사용자 기기에서 돈다. 파일과 네트워크 접근을 막지 않는다. 걸어 두는 제한은 [채점기의 격리 없음](judge.md#격리-없음)에 있다.

## 업데이트

- 확인: 자동 확인이 켜져 있으면 GitHub 공개 API(`releases/latest`)에 인증 없이 묻는다. 요청 머리는 `User-Agent: AlgoBlock/<버전>`과 `Accept`뿐이다. 키, 문제, 기록은 싣지 않는다. 설정(설정 → 업데이트)에서 자동 확인을 끌 수 있다.
- 일정: 앱을 켤 때 마지막 확인에서 24시간이 지났으면 묻고, 그 뒤 24시간마다 묻는다. 마지막 확인 시각과 그때 찾은 새 버전은 자료 폴더의 `updates/settings.json`에 저장한다. 그래서 24시간 안에 다시 켜면 묻지 않고, 저장한 새 버전을 다시 검사해 알린다. 실패하면 1시간 뒤에 다시 묻고, 잇달아 실패하면 2시간, 4시간, 6시간으로 늘린다(6시간이 최대). 성공하면 24시간으로 돌아간다. 확인 하나가 45초 안에 끝나지 않으면 실패로 친다. '지금 확인'을 누르면 일정과 상관없이 그때 묻는다.
- 받는 곳: 이 저장소의 릴리스 파일 주소(`github.com/algocean1204/AlgoBlock-coding-test-helper/releases/download/`)로 시작하는 것만 받는다. 그 밖의 주소는 받지 않는다. GitHub이 저장 서버로 넘기는 주소는 따라간다.
- 견주기: 받으면서 크기와 SHA-256을 센다. GitHub이 주는 파일 해시와 릴리스의 `SHA256SUMS`에 적힌 값을 모두 견준다. `SHA256SUMS`가 있는데 이 파일이 적혀 있지 않거나, 견줄 값이 하나도 없거나, 크기나 해시가 다르면 받은 파일을 지우고 설치하지 않는다.
- 한계: 이 검사는 받는 길에서 깨지거나 바뀐 파일을 막는다. 값도 같은 릴리스에서 오므로, 저장소의 릴리스가 통째로 바뀌었다면 막지 못한다. 설치 파일은 서명하지 않아서 만든 사람을 증명하지 않는다.
- 바꾸기 전: 받은 파일의 SHA-256을 다시 세어 받을 때 견준 값과 같은지 본다. 다르면 지우고 설치하지 않는다. 쓰던 코드를 저장하고, 돌고 있는 채점을 멈춘 뒤 앱을 끝낸다.
- macOS: 받은 dmg를 읽기 전용으로 붙여, 안의 앱의 번들 식별자와 버전이 이 앱의 새 버전과 같은지 본다. 받은 파일에 격리 표시(`com.apple.quarantine`)가 있으면 옆에 복사한 새 앱에서만 뗀다.
- macOS 바꾸기: 앱이 있는 폴더에 쓸 수 있을 때만 바꾼다. 새 앱은 지금 앱 옆에 숨긴 이름으로 복사해 두고, 앱이 끝난 뒤 셸 스크립트(`swap.sh`)가 옛 앱을 치우고 새 앱을 넣는다. 넣지 못하면 옛 앱으로 되돌린다.
- Windows 바꾸기: exe가 있는 폴더에 실제로 파일을 만들 수 있을 때만 바꾼다(Program Files처럼 관리자만 쓰는 곳이면 받은 파일의 위치를 알린다). 새 exe는 지금 exe 옆(`.<이름>.new`)에 복사하고 복사본의 해시를 다시 견준다. 복사는 내용만 하므로 격리 표시(`Zone.Identifier`)가 따라오지 않는다. 그래도 있으면 새 exe에서만 걷는다. 그다음 PowerShell 스크립트(`swap.ps1`)를 앱과 떼어 띄우고, 스크립트가 앱의 프로세스를 잡고 기다리기 시작한 것을 본 뒤에 앱을 끝낸다. 스크립트가 20초 안에 시작하지 않거나 앱의 프로세스를 잡지 못하면(실행 정책이 막는 등) 앱을 끝내지 않는다. 스크립트는 앱(한 파일로 묶은 exe를 풀어 놓는 부모 프로세스까지)이 끝나기를 60초까지 기다리고, 끝나지 않으면 아무것도 바꾸지 않는다. 끝나면 옛 exe를 `.<이름>.old`로 옮기고 새 exe를 제자리에 넣어 연다. 새 앱은 옛 앱이 풀어 놓은 폴더(옛 앱이 끝나면 지워진다)를 가리키는 환경 변수를 물려받지 않는다. 새 앱의 로컬 서버(`http://127.0.0.1:<포트>/`)가 90초 안에 응답해야 성공으로 본다. 넣지 못하거나, 새 앱이 열리지 않거나, 응답하지 않으면 새 앱을 끝내고(먼저 창을 닫게 하고, 5초 안에 안 끝나면 강제로) 옛 exe를 되돌려 연다. 새 exe가 이미 없으면(백신이 격리하는 등) 옛 exe만 되돌린다. 새 exe는 되돌리기에 성공했을 때만 지운다. 새 앱은 스크립트의 출력 파일을 물려받지 않는다. 옛 exe는 스크립트가 지우고, 지우지 못했으면 다음에 켤 때 지운다. 기록은 자료 폴더의 `updates/swap.log`에 남는다. 다음에 켤 때 이 기록을 한 번 읽어(`swap.prev.log`로 옮긴다) 바꾸지 못했거나 되돌렸으면 업데이트 창에 알린다.
- 요청: `/api/update`도 위 '로컬 서버 요청 검사'를 받는다.

## 알려진 한계

- 격리하지 않는다(위 '격리 없음').
- 프로세스 정리와 제한의 빈틈(Windows에서 작업 객체를 쓰지 못한 실행, `setsid`, 메모리 측정 간격, 메뉴의 '끝내기')은 [채점기의 알려진 한계](judge.md#알려진-한계)에 있다.
- 로컬 서버에는 로그인이나 토큰 같은 인증이 없다. 같은 기기의 다른 프로그램은 `127.0.0.1`로 직접 요청할 수 있다. 요청 검사는 브라우저의 교차 출처 요청을 막는 Host, Origin, Sec-Fetch-Site, Content-Type뿐이다.
- '이 PC의 Claude Code' 연결은 `ALGOBLOCK_UI_CLIENT=cli`로 띄웠을 때만 화면에 나온다. 고르면 로컬 `claude -p`를 부른다. 이 연결은 개발용이다.
- tesseract나 `claude` 같은 외부 실행 파일은 PATH에서 이름으로 찾아 부른다. 경로를 고정하지 않는다.
